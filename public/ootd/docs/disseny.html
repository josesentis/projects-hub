OOTD — App Style Manual

The single source of truth for building new dashboard / app screens and components so they match OOTD's design language. Hand this to Claude Code alongside dashboard-restyle/ (a working reference prototype of every current screen). Same brand DNA as the landing page, adapted to a working application.

Golden rule: OOTD is editorial fashion software. Dark, confident navigation chrome; a calm, light gallery canvas for content so clothing photos are the heroes. Restrained type, generous whitespace, hairline borders, a single lime accent used sparingly. Never busy, never "SaaS-template". When unsure, do less.

Accent discipline: at most ~2 lime elements per screen (e.g. the active nav item + the primary action). Everything else is ink / neutral. Lime is a spotlight, not a theme.

1.2 Typography

Three families. Loaded via next/font/google in app/layout.tsx.

Family CSS var Role
Instrument Serif (400, also italic) --serif Page titles (.h1), big numbers/stats, modal titles, the wordmark. Editorial voice. Italic for emphasis only.
Archivo (400–900) --grotesk All UI: body, buttons, nav, inputs, card titles (600–700), table cells.
JetBrains Mono (400/500) --mono Eyebrows, section labels, meta, counts, table headers, badges, item codes. UPPERCASE, letter-spacing .14–.2em, 10–11px.

Type recipes

  • Page title .h1: serif 400, clamp(34px,3.4vw,46px), line-height:1, letter-spacing:-.01em. Emphasis word in <em> (italic).
  • Eyebrow (above every page title): .eyebrow = mono 11px + a lime .dot (6px, glowing). One short label, e.g. EVERYTHING YOU OWN, USAGE & COST.
  • Section label: .section-label = mono 11px .18em faint — separates blocks within a page (ESTIL PER VIBE, CARPETES).
  • Card title: grotesk 700, 15–17px. Big stat number: grotesk 800 clamp(28px,2.6vw,38px) (or serif 400 for a softer, editorial number).
  • Body: grotesk 14–15px, --muted.

1.3 Spacing, shape, motion

  • Radii: cards/modals --r-card:14px; tiles/inputs/image frames --r-tile:8px; pills/buttons/chips --r-pill:100px; modal 18px.
  • Page padding: 30px 40px 80px; max-width 1500px, centred. Topbar 16–40px, min-height 72px, sticky + blur.
  • Rhythm: ~34px between page sections; 18–22px grid gaps; 24–26px card padding.
  • Borders over shadows: every surface gets a 1px --line; shadows are very soft (--shadow). Modals use --shadow-lg.
  • Easing: --ease cubic-bezier(.22,.61,.36,1) (general), --ease-out cubic-bezier(.16,1,.3,1) (entrances). Transitions 200–350ms. Hover lifts translateY(-1px). Keep motion subtle.
  • Icons: simple 1.6px-stroke line icons on a 24px grid, stroke:currentColor (see dashboard-restyle/nextjs/Icons.tsx). 20px in nav, 16–17px in buttons. No filled/duotone icons.

2. Layout

  • App shell: CSS grid grid-template-columns: var(--sidebar-w, 280px) 1fr; min-height:100vh. Class app ootd-dash on the root div (in app/(dashboard)/layout.tsx).
  • Sidebar (.sidebar, dark, sticky full-height): serif italic wordmark "Outfit of the Day" at top → primary .nav → a .nav-group mono divider ("ADMIN") → secondary .nav → spacer → .side-user footer.
  • Main (.main): sticky .topbar (right-aligned .user-chip) over a scrolling .page.
  • Every page opens with a .page-head: an .eyebrow, the serif .h1, an optional .sub (muted count/date), and an optional right-aligned action (button or link).
  • Responsive: sidebar hides below 860px (MobileNav component handles it); two-column page layouts collapse to one column ~1180px; tables get overflow-x:auto.
  • CSS scoping: ALL design system rules are prefixed .ootd-dash so they never collide with Tailwind preflight or landing page CSS. Never add .ootd-dash to landing page elements.

3. Components (classes live in app/(dashboard)/dashboard.css, scoped under .ootd-dash)

Navigation item — .nav-item (.active = lime pill)

Icon + label, pill radius, white-space:nowrap. Hover → --side-2. Active → lime bg, ink text, weight 600. Exactly one active at a time.

Buttons — .btn

  • .btn-primary — lime, ink text. The page's main action (e.g. "Suggereix outfit", "+ Afegeix"). Optional leading icon (star/plus). One per screen.
  • .btn-dark — ink bg, white text. Secondary strong action.
  • .btn-ghost — surface + 1px line. Tertiary.
  • .btn-danger — red text, used ghost-style for destructive.
  • .btn-lg for hero actions. .icon-btn (34px square) for edit/delete/close on cards.

Chips / pills — .chip

Selectable tags (vibes, styles, filters). Default = surface + line; hover → ink border. Selected = .sel (ink fill, white text); .sel.accent (lime fill) for the single "primary" selection like the chosen vibe. Counts use a trailing mono .ct. Lay out in .chips (flex-wrap, 10px gap).

Inputs — .input / .textarea / .select

Surface bg, 1px line, 8px radius, 14–16px padding. Focus → ink border + --accent-soft ring. Always preceded by a mono .label. Selects use a custom chevron background.

Cards — .card (+ .card-pad)

White, 1px line, 14px radius, soft shadow. The base container for everything: outfit cards, folders, wardrobe items, panels. Image areas inside use --r-tile and a fixed aspect-ratio.

Stat card — .stat

Mono .k label → big .v number (grotesk 800 or serif) → muted .m sub. Lay out in an auto-fit grid (minmax(220px,1fr)).

Badges — .badge

Mono micro-labels. Variants: default (neutral), .solid (ink/white, e.g. "Analitzat"), .live (soft-lime status), .ok (ink bg + lime text, e.g. "admin"). For category tags, status, roles.

Tabs — .tabs / .tab

Underline tabs for in-page filtering (wardrobe categories). Active = ink text + 2px ink underline. Counts in a trailing mono .n. Horizontally scrollable.

Table — .table

Surface card with hairline rows. thead th = mono uppercase faint. Rows hover → --surface-2. Numerics use .num (mono, tabular, right-aligned). Two-line cells: .cell-strong + .cell-sub (mono, faint). Wrap in overflow-x:auto.

Toggle — .toggle (.on)

Pill switch, ink when on. For per-row booleans (e.g. "Sense anuncis").

Modal — .scrim > .modal

Blurred scrim, centred. .modal-head (serif title + icon-btns, sticky), .modal-body, sticky .modal-foot with full-width primary + ghost actions. Rises in with --ease-out. Closes on scrim click / ✕ / Esc. Used for item detail, edit, confirms. Keep inside .ootd-dash subtree — do not portal to <body>.

Image placeholder — .empty-thumb

Diagonal-hatch neutral fill with a small mono caption naming the expected photo. Use wherever real user/product imagery will go until it's wired in. Never hand-draw garments.

4. Patterns & content voice

  • Every page: eyebrow → serif title → (sub) → content. Keep the eyebrow short and declarative.
  • Bilingual reality: UI copy is currently Catalan ("Suggereix outfit", "El meu armari", "Afegeix"); eyebrows/labels often English mono. Match the surrounding screen — don't translate existing labels.
  • Counts & meta go in mono, lowercase-friendly ("46 referències · 46 analitzades", "4 outfits", "Usat en 5 outfits").
  • Empty states: centred, faint, one calm line ("No leads yet.") — never loud.
  • Density: comfortable. Prefer fewer, larger, well-spaced elements over dense dashboards. Whitespace is part of the brand.
  • Don't: add gradients, drop-shadow stacks, coloured section backgrounds, emoji (except the ♥ favourite/♥ Favorits), multiple accent colours, or rounded-corner+left-border "callout" boxes. No icon soup.

5. How to build a NEW screen/component (checklist)

  1. Start from the shell: it renders inside .main > .page. Open with a .page-head (eyebrow + serif .h1 + optional action).
  2. Compose from the components in §3 — don't invent new primitives if one fits. Reuse class names so it inherits the system.
  3. Use the tokens (var(--…)) for every colour/space/radius — never hard-code hex or px colours.
  4. Type: serif for titles/numbers, grotesk for UI, mono for labels/meta. Lime only for the one key action/state.
  5. Imagery → .empty-thumb placeholder with a label until real assets exist; fixed aspect-ratio, --r-tile radius.
  6. Add hover/focus states (subtle), keep motion 200–350ms with the shared easings, honour prefers-reduced-motion.
  7. Make it responsive: collapse multi-column layouts ~1180px, tables scroll, sidebar gone < 860px.
  8. Sanity check against the golden rule: dark chrome, light gallery content, restrained type, one accent, lots of air.

7. The stylist app system (Glass / Bone) — current

Sections 1–6 describe the first admin-style system and are kept for the legacy admin screens. Everything the person sees is built on this section. The tokens live in app/globals.css (--p-*, @theme inline), the classes in app/ui.css (ui-*), scoped by .ootd-dash so the landing is never touched.

7.1 Principles

  • Two modes from the same tokens: Glass (dark, aurora, default) and Bone (light). Theme via <html data-theme> + cookie (ThemeScript), "auto" follows the system.
  • Type: Archivo (UI), Instrument Serif italic (the stylist's voice only), JetBrains Mono (system state: steps, counters, dates).
  • Lime (--p-accent) only for the main action and the AI state. Text on lime is --p-accentink; lime as text is --p-accent-text (dark in Bone).
  • Never bg-ink text-white: ink flips with the theme, so white-on-white appears in dark mode. Use bg-ink text-app. Status colours are tokens (danger, ok, warn), never red-50/green-600.
  • Phone first, tested at 390×844 and with the keyboard open. A desktop is a second layout, never a stretched phone.

7.2 Desktop layout (the contract)

Every dashboard screen is an AppPage with a PageHeader (components/layout/*, tested by tests/layout-contract.test.ts). The shell owns the outer padding; a page is a column of at most 75 rem, left-aligned next to the sidebar, and from 1280 px its body is a 12-column grid.

Template Columns Use
dashboard 8 + 4 a main area and secondary context
wide 12 (or 9 + 3 with an aside) grids, tables, lists: Wardrobe, References, Calendar, Profile, admin
focus 8 (+4) one concentrated form
split 6 | 6 two areas of equal weight: Today (the look | the week, the plan, the occasions)

Rules (from the other project, after the "two columns everywhere" attempt was rejected): decide the screen's main task first and pick a named pattern; two equally important areas get equal space; an action that affects the whole page goes in the header or in a full-width command bar (Today's "What have you got today?"), never in a corner of the side column; the aside is secondary context only; rows of cards have the same height, tables aligned columns, no holes. The phone is not touched when the desktop changes: compare 390 px screenshots before and after.

Named patterns used: command bar + split (Today), toolbar + grid (Wardrobe), settings with an anchor index (Profile), table with aligned columns (admin).

The conversation (/stylist) is a full-height pane with its own header (exempt in the contract).

7.3 Doing vs consulting

"I'm wearing it" is one tap, on Today, and undoes with one tap. The wardrobe and the calendar are for consulting and editing, never for marking. Alternatives are first-class: "Change a piece" asks which piece, why, and offers up to five from the person's own wardrobe, ranked without AI (lib/styling/alternatives.ts); "ask the stylist" is the last resort.

7.4 Usage profiles

A person chooses how much of the app exists for them (lib/billing/usage-profiles.ts): Just looks, Wardrobe, Stylist or Custom. A part switched off disappears whole (no tab, no button, no nagging) and nothing is deleted. Custom stays Custom whatever the levels. The plan cuts the choice down; paying again restores it. The look is always a suggestion: never "you didn't follow the look".

7.5 Refs

Callback refs are never written inline (React calls them on every render; if they set state they loop): use useCallback or a ref object. tests/components/refs.test.ts enforces it.

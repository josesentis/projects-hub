2. Synthetic persona (no photos)

  • Each gender + "not set" × build × age bucket × skin tone: result matches the profile.
  • Same user with no photos, 5 generations: same-looking character (seeded defaults).
  • Avatar present, no photos: avatar used as identity (check it isn't a logo/pet/illustration → how it fails).

3. Wardrobe fidelity

  • 1, 2, 4 chosen wardrobe pieces: exact colour/print/logo kept?
  • Wardrobe image with transparent background vs photo with background.
  • Dark garment on dark photo, patterned garments, logos/text on garments (text is the classic failure).
  • Piece the stylist chose but its image failed to download → still produces a coherent outfit.
  • Do pieces not chosen ever sneak in? (they must not)

4. References & trends

  • 0, 1, 2 references: result is inspired by, not a copy of person/outfit.
  • Reference with a person in it: the generated person must not take that face.
  • Contradictions: ocasió "wedding" + vibe "workwear" + gym reference → ocasió wins.
  • Each of the ~40 vibes once (text only): do they look different from each other? (decides if trend images are needed)

5. Visual quality vs landing "style-*" images

  • Full body, shoes visible, relaxed pose, 3–5 garments + accessories, neutral clean background.
  • Hands (extra fingers), feet cut off, mirrored text, weird shoes, floating accessories.
  • Colour of backdrop consistent across outfits (VISUAL_STYLE.background).
  • Decide: keep light neutral backdrop or switch to the dark studio of the landing (one constant in config.ts).
  • Mobile: 768×1344 sharp enough on a retina phone? If not → higher tier / resolution.

6. Context & stylist (Haiku)

  • Season / time of day / weather really change the outfit (winter rain vs summer morning).
  • "Breakfast with a wedding dress in the wardrobe" → dress not used.
  • Empty wardrobe, only references → outfit still generated with described (not owned) pieces.
  • 80-piece wardrobe: shortlist keeps variety; no category starvation.
  • Non-English users (ES/CA): text in their language, IMAGE BRIEF in English.

7. Photo validation (Haiku vision on upload)

Sunglasses, mask, group photo, pet, landscape, screenshot, very dark, blurry, heavy filter, child, statue/drawing. Record false rejects (annoying) and false accepts (bad generations). Tune the prompt in lib/ai.ts › validateUserPhoto.

8. Safety filter behaviour

  • Swimwear / underwear / gym tops, revealing outfits requested by vibes (night-out, soft-glam): how often blocked?
  • What the user sees (genErrors.blocked) and whether a retry with a different style works.
  • Minors: decide policy (DOB under 18?) — currently not handled.

9. Failure & resilience

  • Kill network mid-generation, close tab and reopen: job resumes polling and finishes.
  • Rate limit (spam the button / 2 tabs): only one live job, clean error.
  • Timeout (set TIMING.imageAttemptTimeoutMs low): error + retry reuses brief (no 2nd Claude charge).
  • Cancel in the modal: row deleted, no orphan image in Storage.
  • Confirm outfit → image still there after the saved row is deleted; generate a new one → old unconfirmed image deleted.
  • Stale job (> 3 min) becomes an error with retry.

10. Cost & latency

  • Compare cost/quality with 1 identity photo instead of 3.

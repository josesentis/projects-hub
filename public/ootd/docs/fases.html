OOTD — Implementation plan (phased)

Everything needed to build OOTD, split into phases you implement one at a time. Each phase is self-contained — hand the phase folder to Claude Code, ship it, then move on.

Work them in order: each builds on the last.

📦 Phase 1 — Landing page

Folder: ai/phases/phase-1-landing/ Redesign & build the marketing landing page: dark cinematic editorial site, 3D hero with intro animation, continuous-progress carousels, style slider, lookbook, pricing + notify modal, footer.

  • README.md — full design spec (tokens, type, every section, all interactions).
  • freepik_image_prompts.md — prompts to generate the photography (diverse cast, trendy styling).
  • Reference prototype files: OOTD.html, ootd.css, sections.jsx, app.jsx.
  • Start here — it sets the brand promise everything else must live up to.
  • Status: ✅ Done.

🧠 Phase 2 — Outfit engine & conversational journey

Folder: ai/phases/phase-2-outfit-engine/ Restructure the core app from a form-driven generator into a conversational AI stylist, and define the inputs/outputs of an outfit generation (incl. the 3-layer taste model).

  • README.md — the journey redesign, inputs, outputs, JSON shape, tone, the persistent-vs-today taste layering, and a paste-ready Claude Code prompt.
  • Depends on Phase 1 for tone/promise alignment. The biggest product change — do it second.

🎨 Dashboard restyle + Style Manual (apply now, across phases)

Files: dashboard-restyle/ · ai/DESIGN.md A styling pass that applies the OOTD brand system to the current app: dark editorial sidebar + light gallery content, serif/grotesk/mono type, lime accent, .ootd-dash CSS scoping.

  • ai/DESIGN.md — the app's design system: tokens, type, every component, and a checklist for building new screens. Keep this in the repo so Claude Code generates consistent UI.
  • dashboard-restyle/ — a working reference prototype of every current screen (Home, Calendar, References, Wardrobe + modal, Analytics, Users) + nextjs/ootd-dashboard.css (the system) + TSX components. The CSS is ported to app/(dashboard)/dashboard.css.
  • Use the manual for all new app UI; use the tokens for every colour, never hard-code hex.
  • Status: ✅ Done. CSS applied, sidebar + topbar updated.

📣 Social & favicon assets

Folder: public/favicons/ · public/social/ Share images, favicons, app icons, web manifest and meta tags for the marketing site.

  • public/favicons/ — favicon.svg + PNG 16/32/48, Apple touch icons, Android/PWA icons, maskable variants.
  • public/social/ — og-image.png / twitter-image.png (1200×630).
  • public/site.webmanifest — PWA manifest.
  • Metadata wired in app/layout.tsx.
  • Status: ✅ Done.

✨ Phase 3 — Onboarding & data capture

Folder: ai/phases/phase-3-onboarding/ A modern, progressive onboarding that captures taste, references and wardrobe without a wall of forms — plus the ongoing enrichment loop.

  • README.md — the onboarding flow, capture methods, enrichment, and a paste-ready prompt.
  • Depends on Phase 2 (it feeds the engine's inputs). Do it third — once the engine knows what data it needs, onboarding fills it well.

🖼️ Phase 4 — Outfit imagery (collage V1 + Premium "See it on you")

Folder: ai/phases/phase-4-imagery/ How OOTD shows an outfit. Decision: don't block V1 on generated images — ship a well-designed collage / flat-lay of the user's real garment cut-outs (instant, free, truthful), and reserve a generative "See it on you" try-on for Premium (labelled AI, with fidelity + consent guardrails).

  • README.md — the two-tier strategy, the V1 collage template system, the Premium try-on spec + guardrails, and a paste-ready Claude Code prompt.
  • Pairs with Phase 2 (the engine decides the outfit; this decides how it looks). The collage can ship with V1; the generative try-on is a later Premium surface.

How to use with Claude Code

For each phase: open the phase's README.md, and either paste its "Prompt to paste into Claude Code" section, or tell Claude "read ai/phases/phase-N-.../README.md and implement it." Ship & review one phase before starting the next.

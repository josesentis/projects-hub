Outfit image generation (Claude Haiku → Nano Banana)

Replaces the old text-only outfit + canvas collage. One outfit = **1 Claude call (text, no images)

  • 1 Nano Banana call (image)**. Code lives in lib/outfit-gen/.

Flow

POST /api/outfits ──► row saved_outfits (status=pending) ──► 202 {id}
        │                       │
        │                       └─ after(): runOutfitGeneration()
        │                            1. planning   Claude Haiku 4.5 (text only)
        │                            2. rendering  Nano Banana (1 image call, ≤2 attempts)
        │                            3. done       WebP → Storage → collage_url
        └─ client polls GET /api/outfits/[id] every 2s → step-by-step modal

Statuses: pending → planning → rendering → done | error(errorCode). A job that never reports back for 3 min is settled as error/stale on the next poll. POST /api/outfits/[id]/retry re-runs only the image step when the stylist brief is already stored (Claude is not paid twice).

Token / cost levers (in the order they matter)

  1. Claude sees no images — it reads the descriptions already stored by the analysis step.
  2. Haiku 4.5 for the text (OUTFIT_TEXT_MODEL in config.ts). ~$0.003/outfit.
  3. Wardrobe shortlisted in code to 15 pieces (favourites, least-worn, category-balanced); references capped at 8; descriptions truncated to 240 chars; max_tokens 1100.
  4. Situation (season / time of day / weather via Open-Meteo) computed in code, injected as one line.
  5. Nano Banana gets only what matters: ≤3 identity photos, ≤4 wardrobe pieces chosen by the stylist, ≤2 references cited by the stylist; all resized to 768px JPEG.
  6. Image model is the cheap tier (gemini-2.5-flash-image, ~$0.039/image, 768×1344). Override with GEMINI_IMAGE_MODEL when quality matters more than cost.
  7. Retries: one extra image attempt only for transient errors (429/5xx/timeout/no_image). blocked and corrupt never retry.
  8. One live generation per user: a double click joins the running job.

Not done on purpose: a hash cache (the stylist output differs on every call, so identical inputs never repeat) and Anthropic prompt caching (the static part of the prompt is far below Haiku's minimum cacheable size).

Who appears in the image

Situation Behaviour
User has photos First 3 by order are sent as identity images; strict identity rules in the prompt. Profile stats are only a proportions hint.
No photos, has avatar Avatar is the single identity image.
Neither Synthetic model from profile data (gender, age from DOB, height, weight, build, hair, skin). Missing attributes are filled deterministically from the user id, so the character is stable across generations. Gender is never guessed.
Photos fail to download Falls back to the synthetic flow instead of failing.

Profile photos (max 5) are validated on upload by one tiny Haiku vision call (validateUserPhoto): no person / several people / face hidden / low quality are rejected with an explanation. The check fails open if Anthropic is down.

Input priority (encoded by order — the model weighs earlier content more)

identity photos → wardrobe pieces → references → text (base style, subject, image roles, outfit brief, avoid-list). Conflict rule given to the stylist: occasion > style > vibe > references; wardrobe pieces are used only if they fit (no wedding dress for breakfast).

The landing example images are not sent on every call (they would burn the image budget and make the model copy their person/clothes). Their look is encoded in config.ts (VISUAL_STYLE).

Tuning (no logic changes needed)

lib/outfit-gen/config.ts: aspect ratio, max height, WebP quality, input limits, timeouts, shortlist size, VISUAL_STYLE (photo / light / background / clothing), NEGATIVE_RULES, IDENTITY_RULES. prompt.ts only assembles these blocks. The stylist's output format (PIECES USED, IMAGE BRIEF) is in lib/ai.ts › generateOutfit.

Errors

OutfitGenError codes: not_configured, input_missing, rate_limited, timeout, blocked, no_image, corrupt_image, upstream, storage, stale, internal (+ retryable). The UI shows a translated message and a "Try again" button for retryable ones.

Env

ANTHROPIC_API_KEY, GEMINI_API_KEY (required), GEMINI_IMAGE_MODEL (optional), CLAUDE_MONTHLY_BUDGET_USD / GEMINI_MONTHLY_BUDGET_USD (optional, admin analytics shows what's left). Run migration 0013_outfit_images from /api/admin/run-migrations (same SQL in drizzle/0010_outfit_images.sql).

Known caveats / follow-ups

  • The job runs in after() with maxDuration = 60. Measured generation: ~6–8s image + ~3s text. If the host ever caps functions below that, move the job to a Netlify Background Function (runOutfitGeneration is already host-agnostic; only the dispatch in app/api/outfits/route.ts changes).
  • Generated images live at outfit-images/{user}/{outfit}.webp (public bucket). A confirmed outfit keeps the same file; discarding/replacing an unconfirmed one deletes it.
  • Legacy outfits keep their canvas collages (lib/collage-generator.ts, OutfitCollage) and the /api/worn-outfits/[id]/collage route. Delete them when old outfits are purged (see ROADMAP).
  • No usage limits are enforced right now (test phase, by decision). weeklyCredits is unused here.
  • Photos are sent to Google; no consent flow yet (current users are friends). Add a T&C acceptance push before the public launch.

Yafa (yafafits.com)

Source: https://x.com/YaelBienenstock/status/2053808661605003490
Founder: Yael Bienenstock (@YaelBienenstock)
Status: Waitlist / early access (as of May 2026) — not yet publicly available on App Store
Platform: Mobile-first (iOS, likely)
Website: https://yafafits.com

What it does

Yafa is an outfit-logging app built around a social feed and a 3D avatar. Core features:

  1. Outfit logging — one photo logs the full fit. Auto-detects and tags every clothing item automatically (no manual tagging).
  2. 3D mini-avatar — builds a personalised 3D representation of the user wearing the outfit. The avatar remembers context: clothes, weather, activity, date.
  3. Social feed — Instagram-style feed where users share outfits. Followers can like and comment. Discovery of other people's looks.
  4. Shareable outfit cards — generates a styled card from the outfit photo, shareable on social media or via direct message.
  5. Shoppable closet — auto-tagged items make the closet browsable and shoppable (find similar items to buy).

Strengths (features we should learn from)

  • 3D avatar — highly visual and differentiated. Makes logging feel like a game rather than a chore.
  • Auto-tagging — zero friction. One photo and the entire outfit is catalogued. We require manual upload and AI analysis triggered by the user.
  • Social layer — community/social feed is a strong retention mechanism. Turns a private tool into a shared experience.
  • Shareable cards — a viral loop built in. Every shared card is organic marketing.
  • Shoppable closet — monetisation angle + utility combined.

Weaknesses / gaps (our opportunities)

  • No AI outfit suggestions — Yafa logs what you wore; it does not suggest what to wear. We generate daily outfit ideas based on wardrobe + weather + preferences.
  • No wardrobe planning — focused on logging the past, not planning the future.
  • Mobile only — no web app. We work on any device.
  • No Pinterest/reference board integration — we let users import style inspiration directly from Pinterest boards.
  • Waitlist / not launched — we are already live. First-mover advantage in the AI suggestions space.
  • No daily reminder / cron — we have push notifications and a daily outfit suggestion email infrastructure.
  • No privacy focus mentioned — we keep data in the user's own account, no public sharing required.

cv.nan.builders (ATSKiller by Manfred)

Source: Tweet by @nan_builders (Manfred) Status: Live / public beta (May 2026) Platform: Web Website: https://cv.nan.builders

Nota: no és competència directa en fashion. S'analitza com a referència d'UX, negoci i decisió tècnica per a una app AI de nicho.

What it does

Suite de 3 eines gratuïtes per optimitzar el CV per a sistemes ATS:

  1. CV Analyser — puja CV (PDF/DOCX/TXT/MD, màx 3 MB), anàlisi instantàni amb puntuació en 6 dimensions, recomanacions concretes, export a PDF.
  2. CV Editor — editor estructurat basat en una plantilla d'un influencer conegut (@DanielBlancoSWE). Editor intencionalment restrictiu per no deixar que l'usuari trenqui l'optimització ATS. Traducció AI integrada. Màx 202 paraules.
  3. CV vs Job Offer Matcher — compara CV amb una oferta concreta, detecta keywords que falten, calcula % de match. Puja CV + oferta (PDF/DOCX).

Business model

  • Completament gratuït — "Herramienta gratuita para la comunidad"
  • Lead magnet per Manfred — Manfred és una agència de reclutament tech. L'eina genera tràfic i credibilitat; la conversió és cap als seus serveis de reclutament.
  • Software com a màrqueting — l'autor ho diu explícitament: "constatar que se puede hacer software como marketing y, a la vez, seguir haciendo un marketing honesto"
  • Cap registre necessari — zero friction, zero email capture en el punt d'entrada
  • API spending cap — límit de despesa explícit per no arruïnar-se: "La API tiene un límite de gasto para que no me arruinéis"

Tech stack

  • AI: Google Gemini (no Claude, no GPT)
  • Storage: Zero — "Tu CV solo se almacena en tu local storage" — cap dada al servidor
  • Feedback: botó de feedback que crea issues directament (probablement GitHub Issues o Linear)
  • Stack web: desconegut, però sembla SPA lleugera (respon ràpid, sense autenticació)

Key UX decisions (aprendre-ne)

Decisió Per què Aprenentatge per nosaltres
Sin registro Elimina la barrera d'entrada. L'usuari obté valor abans de donar res. Considerar un mode "prova sense registre" per l'anàlisi inicial de wardrobe
Dades en localStorage Privacitat com a feature. Sense GDPR headaches. Bones pràctiques de privacitat com a argument de màrqueting
Editor restrictiu L'usuari no pot "trencar" el producte. Protegeix la qualitat del output. El nostre AI outfit podria ser igual de prescriptiu — no deixar editar massa
Template d'influencer Credibilitat instantànea + distribució orgànica del influencer Buscar col·laboració amb un influencer de moda per a plantilla de wardrobe
Feedback → issues Gestió de backlog pública i transparent Implementar botó de feedback que creï issues (Linear/GitHub)
API spending cap Sostenibilitat de la beta sense model de pagament Ja ho tenim planificat (crèdits); implementar-ho aviat
Límit de fitxer (3 MB) Controla la despesa de tokens d'AI Per a nosaltres: límit de mida d'imatge en wardrobe upload
Múltiples eines en suite Retenció: l'usuari torna per eines diferents. Cross-selling intern. Roadmap de suite: analyze → suggest → track → share

Weaknesses / gaps

  • Cap model de monetització directe — depèn 100% del negoci principal de Manfred
  • No té retenció pròpia (sense compte, sense historial)
  • L'eina pot desaparèixer si Manfred decideix deixar-la
  • No té loop viral propi (no genera contingut compartible)

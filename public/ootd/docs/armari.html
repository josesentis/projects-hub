Next iteration — wardrobe photo → reconstructed product shot (replaces remove.bg)

Status: not started. Do it after the outfit image flow is validated with real users.

Target look

The wardrobe-*.webp images on the landing: pieces laid out as clean product shots on a dark/neutral backdrop (3:4), one piece per image, consistent lighting, no person, no hands, no wrinkles from the original photo. STUDIO_RECIPE in lib/gemini.ts currently says pure white; switch to the colour the product team picks (keep it a single constant so the whole wardrobe stays consistent).

What already exists (inert)

  • lib/ai.ts › detectGarments() — Claude lists the garments in a photo (name/category/description).
  • lib/gemini.ts › reconstructGarment(source, garment) + buildGarmentPrompt + STUDIO_RECIPE.
  • geminiImageCostUsd in lib/usage-cost.ts.
  • ai/IMAGE_PIPELINE_TODO.md has the earlier plan (max 2 garments per photo, discard the original, immediate vs background processing). Its "B. AI collage" section is obsolete — outfits are now photos of a person.

Proposed pipeline (1 vision call + N image calls per upload)

  1. Upload → shrinkForApi → one analyzeWardrobeItem/detectGarments call (Haiku, ≤2 garments).
  2. For each garment: reconstructGarment (1 Nano Banana call, reference = the user's photo, aspect 3:4, input resized to 768px like the outfit flow).
  3. Store wardrobe/{id}.webp, save the item with analyzed=true, drop bg_removed semantics.
  4. Keep the original only until step 3 succeeds, then delete it (decided earlier).
  5. Usage events: feature='wardrobe_reconstruct', provider='gemini'.

Things to validate before rolling out

  • Fidelity: exact colour/print/logo must survive. Test with 20 real photos (selfies, mirror shots, folded clothes, worn). If details drift, add the original crop as a second reference and lower temperature.
  • Occlusion (jacket covering shirt): decide whether to reconstruct only fully visible garments.
  • Latency: 2 calls ≈ 15s → show a skeleton card per piece, process in the background with the same after() + polling pattern as outfits (see lib/outfit-gen/pipeline.ts, status.ts).
  • Cost: ~$0.04/piece + ~$0.003 detection. Compare with remove.bg's per-credit price.

Cleanup when done

Remove lib/bg-removal.ts, app/api/wardrobe/[id]/bg, REMOVEBG_API_KEY, @imgly/background-removal, removebg usage events/labels in admin analytics, the bg_removed column usage, the admin placeholders/collages tooling and public/wardrobe-placeholders/. Then feed the reconstructed images to the outfit generator as wardrobe inputs (already supported: getWardrobeItemsByIdsDb → loadForModel).

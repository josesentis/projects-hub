OOTD — Reimagining the user journey (conversational AI stylist)

A brief for Claude Code to evolve the OOTD app from a form-driven generator into a warm, conversational AI stylist — matching the promise of the landing page:

"A stylist that actually knows you. It learns your wardrobe, your references and your taste — then dresses you, every morning."

1. The problem with the current journey

Today the app is a form: prompt box → vibe list → editable categories → reference folders → "Generate" → one outfit of N pieces. It works, but it feels like configuring software, not like talking to a stylist. Every decision is front-loaded onto the user before anything happens, and the single rigid output gives no room for the back-and-forth that real styling is.

North star: it should feel like texting a stylish friend who already knows your closet. Not "fill this in and I'll compute a result" — but "Morning! It's drizzly and you've got that studio day — here's what I'd wear. Want it warmer?"

2. Principles for the new journey

  1. Proactive, not reactive. OOTD opens with a suggestion already made, not an empty prompt. The user reacts and refines instead of configuring from zero.
  2. Conversation is the primary interface. The prompt box becomes a chat thread. Vibes, categories and references become things you can mention or tap, not mandatory form fields.
  3. Context does the heavy lifting. The app already knows the weather, time, calendar and wardrobe — so it shouldn't ask the user to restate them. Show that it knows ("18° and clearing up ☀️") to build trust.
  4. Refinement is cheap and natural. "make it warmer", "swap the shoes", "I want to wear my new jeans", "more sporty" — all handled in-conversation, regenerating only what's needed.
  5. Warm, human, brief. Short sentences, first person, a little personality. Never clinical. (See §6.)
  6. Always escapable to control. Power users can still tap to pin a vibe, lock an item, or open the wardrobe — the structure isn't gone, it's demoted from gate to option.

3. The reimagined journey (happy path)

A. The morning open (proactive) Instead of an empty generator, the app opens on today's suggestion, framed as a message:

☀️ Good morning, Jose. It's 14° and drizzly in Barcelona, and you've got Studio day → dinner at 8. Here's what I'd wear today: [ Look card: a single styled outfit, hero image/flatlay + the pieces ] Layered for the rain, easy to dress up for tonight. Want to tweak anything?

[ Love it ] [ Make it warmer ] [ More sporty ] [ Swap a piece ] [ Show another ]

The user lands in a conversation already in progress. No blank slate.

B. Refine by chatting The quick-reply chips are shortcuts; the user can also just type. Each refinement is a turn in the thread, and OOTD answers with an updated look + a one-line rationale:

🧑 more sporty, I'm cycling there 🤖 Got it — swapped the trousers for your black joggers and the boots for the Sambas. Still warm enough for 14°. [ updated look ]

C. Steer with vibe / occasion (optional, inline) Vibes and occasions are surfaced as suggestible chips, not a required list:

Today feels like… [ Quiet Luxury ] [ Streetwear ] [ Old Money ] [ + tell me ]

Tapping one (or typing "something more Y2K") re-styles. The previously-selected categories live behind a small "Adjust what I consider" control, not on the main path.

D. Anchor to a piece or a reference (optional) "I want to wear my new white boots" → OOTD builds the look around that item. "Use my Pinterest 'autumn' folder" → it leans on that reference set. These are mentions in the chat or taps in a slim tray, not mandatory steps.

E. Commit When the user is happy: [ Wear this ] → marks it worn (feeds the "don't repeat" history), optionally adds a calendar/notification, and can save to the lookbook. Done before coffee.

F. Want options? "Show another" / "give me 3" returns a small set of distinct looks to swipe — reconciling the landing's "3 looks ready for you today." (See §5 on free vs premium.)

4. INPUTS — the signals OOTD should consider

Group them so the app gathers most automatically and only asks when it adds real value.

4b. How vibes & styles layer (persistent taste vs today's intent)

A key question: do the user's vibes/styles live in settings or at generation time? Both — in three layers, so the user never re-picks their taste every morning, but can always override it.

  1. Style identity (persistent — user profile). The user's default self, set once in onboarding and rarely edited. "I wear a lot of workwear" is stored here and applied to every outfit — dinner or work — without restating it. Store it weighted, not binary: e.g. Workwear 70% · Minimal 20% · Streetwear 10%, so the lean dominates but outputs still vary. Evolves automatically from accept/reject history.
  2. This-moment intent (per generation — conversational / chips). Today's deviation. Most days the user touches nothing and Layer 1 applies. But "I have a wedding today" (typed, or an occasion chip) temporarily overrides the workwear lean for that one generation. It's ephemeral — tomorrow returns to the profile automatically; nothing to undo.
  3. Occasion / dress code. Either volunteered in chat or tapped from the Work · Gym · Dinner · Event · Chill chip row (and, if the device calendar is connected, inferred). Sets the formality target.

The golden rule: occasion/intent overrides persistent identity for formality, but the persistent taste still shapes the aesthetic. So a wedding for a workwear-leaning user → formal, but in their DNA (a clean, minimal-cut suit/dress — not a flashy tuxedo), which is what keeps it feeling "theirs". When today's intent conflicts with the profile, OOTD should say so, not switch silently: "Going dressier than your usual workwear since it's a wedding — keeping it minimal so it still feels like you." That transparency builds trust.

UX: profile lives on a "Your style" settings page (weighted vibes, colours you avoid, fit, modesty — configured once); at generation a suggestible chip row shows your default pre-selected, and tapping one or typing an occasion affects today only. Do nothing → Layers 1 + 3 generate friction-free.

Ambient / contextual (automatic — never ask the user to type these)

  • Weather today: temperature (high/low), "feels like", precipitation %, wind, UV/sun, humidity. Drives warmth, layers, waterproofing, fabrics.
  • Location: city/region (for weather + cultural/seasonal norms), indoor vs outdoor day.
  • Time & date: time of day (morning vs going-out), day of week, season.
  • Occasion / what today is: ⚠️ OOTD's own calendar only stores outfits (today's + past), NOT external events — so it cannot infer "wedding" on its own. The occasion must come from: (a) conversation ("I have a wedding at 5"), or (b) a quick chip row at generation (Work · Gym · Dinner · Event · Chill). Future/premium: optionally connect the device calendar (Google/Apple) to recover automatic dress-code inference. The outfit history calendar is still used for no-repeat logic and "not worn in 3 weeks".

User / taste (learned, persistent)

  • Style profile / taste vector: learned from onboarding + saved references + accept/reject history. This is the moat — "knows you".
  • Reference folders: saved looks, screenshots, Pinterest-style boards the user curated.
  • Preferred vibes / aesthetics: the ones they lean on (Quiet Luxury, Streetwear…).
  • Fit & comfort preferences: loose vs fitted, no heels, always layers, colours they avoid, modesty preferences.
  • Wear history: what they've worn recently → avoid repeating the same pieces too soon; surface under-worn items.

Wardrobe (the inventory it styles from)

  • Items the user owns: category, colour, fabric/warmth, formality, pattern, season, and photos. (Free tier ~40 items.)
  • Availability: in laundry / packed / unavailable → exclude.
  • Pairing memory: combinations the user has worn/loved before.

This-moment intent (optional, conversational)

  • Free-text request / mood: "comfy but cute", "I feel like wearing colour", "all black".
  • Occasion override: when today differs from the calendar ("date tonight").
  • Anchor item: "build around my new boots".
  • Constraints: "it's a long day on my feet", "no jacket, I'll be inside".

Rule of thumb: infer everything in the first two groups silently; let the user volunteer the fourth group through chat. Only ask a question when a real ambiguity would change the result (e.g. "Indoors all day or out in the rain?").

5. OUTPUTS — what a generation should return

Your current output is a single outfit of N pieces. To feel like a stylist (and match the landing), enrich it — even if the default view still shows one primary look.

For each suggestion return:

  1. The look — the ordered set of wardrobe pieces (top, bottom, outerwear, shoes, accessories), each linked to the real item in the user's wardrobe (with its photo). Flag any gap ("you don't own a light rain jacket — here's the closest thing").
  2. A one-line rationale — why this, today, in the assistant's voice. "Layered for the drizzle, dressy enough for dinner." This single line is what makes it feel intelligent rather than random.
  3. A title / vibe tag — e.g. "Studio → Dinner" or "Off-duty sporty". Useful for the lookbook + quick scanning.
  4. Confidence / context chips — small, honest signals: 14° · drizzle · bridges 2 events · you haven't worn this in 3 weeks.
  5. Refinement affordances — per-piece swap (give 2-3 alternatives for any slot the user taps) and global moves (warmer / dressier / sportier / different colour / surprise me).
  6. Alternates — 0 by default in the thread, but "show another" / "give me options" returns 2-3 distinct looks (the landing's "3 looks ready"). Suggest gating: free = 1 daily look + unlimited swaps; premium = multiple full looks & re-styles on demand (aligns with the pricing section).

So: the atomic output is still one outfit, but wrapped with reasoning, context, swap-alternatives, and an optional small set of full alternates. That's the difference between "a generator" and "a stylist".

6. Tone & copy guidelines

  • First person, warm, brief. "Here's what I'd wear" — not "Outfit generated."
  • Show you know the context, lightly. A weather/calendar nod once per morning, not on every line.
  • One idea per message. Short bubbles, like texting.
  • Personality without gimmicks. A little warmth and the odd emoji (☀️🧥) is fine; avoid robotic status text ("Processing your 4 selected categories…").
  • Honesty over hype. If the wardrobe lacks something, say so kindly and offer the closest option.
  • Never block on configuration. Questions only when they change the outcome.

7. Migration notes (don't throw away what works)

  • The vibe list, category editor and reference folders still exist — relocate them from mandatory pre-generation form to optional, inline or in a side tray ("Adjust what I consider", per-piece swaps, a vibe chip row).
  • Keep the wardrobe and reference ingestion exactly as-is — that data is the input engine described in §4.
  • The generate action becomes implicit (auto on open) + conversational (every chat turn re-generates as needed). A manual "new look" button can remain.

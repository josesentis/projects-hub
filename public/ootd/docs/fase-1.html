Handoff: OOTD — AI Fashion Assistant landing page

Overview

OOTD ("Outfit of the Day") is an AI fashion assistant: it learns the user's wardrobe, references and taste, then suggests the perfect outfit for today's weather, calendar and mood. This package is the landing / marketing page — a dark, cinematic, scroll-driven editorial experience with a 3D hero, draggable carousels, a style-slider, an outfit lookbook, and a pricing section (Free is live, Premium is "coming soon").

⚡️ Read this first — how to use this package

The files in this bundle (OOTD.html, ootd.css, sections.jsx, app.jsx) are a complete, working prototype built with React-via-Babel. Everything in it is final and intentional: layout, copy, colors, type, spacing, AND the interaction logic. Your job is to port it into the target codebase faithfully — not to redesign or reinterpret it.

Follow these rules so the result matches the prototype 1:1:

  1. Keep the structure, copy, and CSS exactly. ootd.css is the source of truth — port it verbatim (as a global stylesheet, CSS modules, or Tailwind @layer — your call, but do not change values). Every measurement, token, gradient and breakpoint in it is deliberate.
  2. Port the interaction logic almost verbatim. The hard parts — the hero 3D motion, the continuous-progress carousel, the inertia slider, the modal — are all plain requestAnimationFrame + pointer-event logic in sections.jsx / app.jsx. This logic is framework-agnostic and already correct. Lift it into your components mostly as-is (move per-frame state into useRef, run the rAF loop in useEffect, drive transforms imperatively). Do not rewrite these engines from scratch or swap them for a generic carousel library — you'll lose the exact feel the user approved. (Framer Motion / GSAP are fine additions for entrance reveals, but the carousel/slider/hero engines should stay as the rAF logic shown here.)
  3. Componentize, don't reinvent. Split sections.jsx into one component per section (Hero, Manifesto, Featured, Trends, Lookbook, Pricing, NotifyModal, Footer) under e.g. components/. Convert to .tsx and add types. Keep the same DOM/class structure so ootd.css keeps working.
  4. Drop ONLY this scaffolding: the in-browser Babel <script> tags, the <image-slot> web component (image-slot.js), and the Tweaks panel (tweaks-panel.jsx + useTweaks + the whole <TweaksPanel> block in app.jsx). These are prototype-only tools. Replace <image-slot>/Slot with real <img> / next/image (see Assets). For the Tweaks-driven options (theme, scroll-reveal variant, carousel style, accent), just hard-code the defaults listed in this doc — you don't need the panel.

If you're unsure about any detail, the answer is "match the prototype." Open OOTD.html in a browser to see/feel the target.

4. Today's Looks — continuous-progress carousel (#looks)

  • Header: eyebrow "● TODAY'S LOOKS"; serif title "Your best fits, one tap away."; right side controls = two 54px circular buttons (← →, fill lime on hover) + a mono counter 01 / 05.

⚠️ THIS IS THE TRICKIEST COMPONENT — READ THIS WHOLE BLOCK BEFORE CODING IT. It is NOT a normal carousel and must NOT be built with a carousel library, CSS scroll-snap, or index-based slide swapping. If you build it from activeIndex state + CSS transitions, the smooth fractional motion is lost and it will feel "jumpy" — that's the #1 failure mode. Port the reference code below almost verbatim.

How it works (the model)

A single continuous fractional position pos ∈ [0, n-1] drives everything. pos = 0 → card 0 centred; pos = 1 → card 1 centred; pos = 1.5 → halfway between cards 1 and 2, with both rendered in symmetric mid-perspective. There is no integer "active index" as the source of truth — the centred card is merely Math.round(pos).

Two numbers, both kept in a ref (never React state, to avoid per-frame re-renders):

  • pos — where the carousel is right now (what you render).
  • target — where it's heading (set by drag/buttons/scrub).

One requestAnimationFrame loop runs for the lifetime of the component. Every frame:

  1. If not dragging, ease pos toward target: pos += (target - pos) * 0.12 (the lerp — THIS is the smoothing; snap pos = target when within 0.0008).
  2. Call apply(), which positions every card from its continuous offset off = idx - pos.

apply() reads pos and, for each card, sets inline styles directly (no transitions):

off = idx - pos;  a = Math.abs(off);
// coverflow (default):
transform = `translateX(${off * W*0.62}px) translateZ(${-Math.min(a,3)*130}px) `
          + `rotateY(${clamp(off*-22, -46, 46)}deg) scale(${Math.max(0.68, 1 - a*0.14)})`;
opacity   = a > 2.4 ? 0 : Math.max(0.32, 1 - a*0.4);
zIndex    = 100 - Math.round(a*10);
metaOpacity = Math.max(0, 1 - a*1.4);   // only the near-centre look shows its name/weather

W = slide width (≈380). step = px per one card-step = W*0.62 (≈235) for coverflow. Because off is continuous, the cards interpolate smoothly and fractionally as pos changes — that's the whole point.

Interactions (all just set pos/target)

  • Drag the stage (pointer events on .car-stage): on down, store startPos = pos, dragging = true. On move, pos = target = clamp(startPos - dx/step, 0, max) — 1:1 finger tracking, fully fractional (you literally watch cards rotate through the in-between states). Track velocity. On up, dragging = false and apply flick inertia: target = round(target - (vel/step)*4); the lerp then eases there. A moved flag (|dx|>5px) suppresses the click so a drag doesn't also "select" a card.
  • ← / → buttons: target = round(target) ± 1 (clamped to [0, max]).
  • Click a card: if (!moved) target = idx.
  • Progress bar = scrubber: pointer-down/drag anywhere on .progress sets pos = target = fraction * max (continuous); on release target = round(target) to settle on a card. The fill is a continuous readout: progressFill.style.transform = scaleX(pos / max) updated every frame inside apply().
  • Counter text = round(pos)+1, zero-padded; the centred card also toggles an .active class.

Reference implementation (port this closely)

function Featured({ n }) {                  // n = number of looks
  const trackRef = useRef(null), fillRef = useRef(null), countRef = useRef(null), progRef = useRef(null);
  const eng = useRef({ pos:0, target:0, max:n-1, step:235, dragging:false, startX:0, startPos:0, vel:0, lastX:0, moved:false });
  const clamp = (v,a,b) => Math.max(a, Math.min(b, v));

  const apply = () => {
    const track = trackRef.current; if (!track) return;
    const slides = track.querySelectorAll('.slide');
    const W = slides[0]?.offsetWidth || 380;
    const e = eng.current; e.step = W * 0.62;
    slides.forEach((s, idx) => {
      const off = idx - e.pos, a = Math.abs(off);
      s.style.transform = `translateX(${off*W*0.62}px) translateZ(${-Math.min(a,3)*130}px) rotateY(${clamp(off*-22,-46,46)}deg) scale(${Math.max(0.68,1-a*0.14)})`;
      s.style.opacity = a > 2.4 ? 0 : Math.max(0.32, 1 - a*0.4);
      s.style.zIndex = 100 - Math.round(a*10);
      s.classList.toggle('active', Math.round(e.pos) === idx);
      const meta = s.querySelector('.meta'); if (meta) meta.style.opacity = Math.max(0, 1 - a*1.4);
    });
    if (fillRef.current) fillRef.current.style.transform = `scaleX(${clamp(e.pos/e.max,0,1)})`;
    if (countRef.current) countRef.current.textContent = String(Math.round(e.pos)+1).padStart(2,'0');
  };

  useEffect(() => {                          // ONE loop for the component's life
    const e = eng.current; let raf;
    const loop = () => {
      if (!e.dragging) { e.pos += (e.target - e.pos) * 0.12; if (Math.abs(e.target - e.pos) < 0.0008) e.pos = e.target; }
      apply();
      raf = requestAnimationFrame(loop);
    };
    raf = requestAnimationFrame(loop);
    const onResize = () => apply(); window.addEventListener('resize', onResize);
    return () => { cancelAnimationFrame(raf); window.removeEventListener('resize', onResize); };
  }, []);

  const setTarget = v => { eng.current.target = clamp(v, 0, eng.current.max); };
  const go = d => setTarget(Math.round(eng.current.target) + d);

  const onDown = ev => { const e = eng.current; e.dragging = true; e.startX = e.lastX = ev.clientX; e.startPos = e.pos; e.vel = 0; e.moved = false; ev.currentTarget.setPointerCapture?.(ev.pointerId); };
  const onMove = ev => { const e = eng.current; if (!e.dragging) return; const dx = ev.clientX - e.startX; if (Math.abs(dx) > 5) e.moved = true; e.vel = ev.clientX - e.lastX; e.lastX = ev.clientX; const v = clamp(e.startPos - dx/e.step, 0, e.max); e.pos = v; e.target = v; };
  const onUp = () => { const e = eng.current; if (!e.dragging) return; e.dragging = false; setTarget(Math.round(e.target - (e.vel/e.step)*4)); };

  const scrub = x => { const e = eng.current, r = progRef.current.getBoundingClientRect(); const f = clamp((x-r.left)/r.width, 0, 1); e.pos = f*e.max; e.target = e.pos; };
  const pDown = ev => { ev.preventDefault(); ev.stopPropagation(); scrub(ev.clientX); const mv = e2 => scrub(e2.clientX); const up = () => { window.removeEventListener('pointermove', mv); window.removeEventListener('pointerup', up); setTarget(Math.round(eng.current.target)); }; window.addEventListener('pointermove', mv); window.addEventListener('pointerup', up); };
  // JSX: <div class="car-stage" onPointerDown/Move/Up/Cancel/Leave={...}>
  //        <div class="car-track" ref={trackRef}> {looks.map => <div class="slide" onClick={() => { if (!eng.current.moved) setTarget(idx); }}>…</div>} </div>
  //      </div>
  //      <div class="slider-bar"><div class="progress" ref={progRef} onPointerDown={pDown}><div class="progress-fill" ref={fillRef}/></div><span class="slider-hint">Drag to explore</span></div>
}

Required CSS / DOM (or the math breaks)

  • .car-stage{ position:relative; height:600px; perspective:1800px; cursor:grab; touch-action:pan-y; }
  • .car-track{ position:absolute; left:50%; top:0; width:0; height:100%; transform-style:preserve-3d; } — width 0 + left:50% makes each absolutely-positioned slide's translateX(0) land dead-centre.
  • .slide{ position:absolute; left:-190px; width:380px; } (left = −W/2 to centre it on the track origin). The frame inside is height:520px.
  • No transition on .slide. The rAF lerp is the animation; a CSS transition fights it and causes lag/jank. (You may transition box-shadow only.)
  • .progress{ position:relative; height:3px; background:var(--line); cursor:pointer; touch-action:none; } with .progress-fill{ position:absolute; inset:0; transform-origin:left; transform:scaleX(0); background:var(--accent); }.

Common failure modes (the bugs to avoid)

  1. Built with activeIndex + CSS transitions → snaps between integer slides, no fractional in-between. ✗ Use continuous pos + rAF lerp.
  2. setState inside the loop → React re-renders 60×/s, stutters. ✗ Keep pos/target in a ref; mutate DOM directly in apply().
  3. No persistent rAF loop (e.g. only animating on events) → drag works but release/inertia/scrub don't ease. ✗ One loop runs always.
  4. A CSS transition left on .slide → double-animates, feels laggy. ✗ Remove it.
  5. Track not width:0; left:50% → cards offset wrong / first card not centred.
  6. Driving pos from scroll instead of pointer — this is a drag/scrub control, independent of page scroll.
  • Slide data (name / weather tag): The Commute / MON·14°DRIZZLE · Studio Day / TUE·19°CLEAR · Gallery Opening / WED·16°CLOUD · Dinner, 8pm / THU·12°CRISP · Slow Sunday / SUN·22°SUN.
  • Two other visual styles exist in the prototype (flat, spotlight) as Tweaks; ship coverflow (above) as default — the others are optional.

5. Tell it a vibe — style slider (#styles)

A horizontal, inertia-based draggable slider with a scrubable progress bar (this is the "premium scroll animation, inside a slider" the user asked for).

  • Header: eyebrow "● STYLE UNIVERSES"; serif title "Tell it a vibe."; right paragraph "Steer the assistant toward an aesthetic and it re-styles your wardrobe to match."
  • .slider-vp is overflow:hidden, full-bleed (cards extend to the right edge); .slider-track is a flex row (gap:16px, padding-inline:var(--gutter)) of equal vertical cards .trend (width:clamp(260px,23vw,360px), aspect-ratio:3/4.3).
  • Each card: an absolutely-positioned .timg (image, scaled 1.14 and parallaxed, object-position: top so portraits show the face/upper body — a "plano americano" framing — not a centre crop), a bottom gradient overlay (linear-gradient(180deg, rgba(10,10,10,.05) 35%, rgba(10,10,10,.82))), and a .tlabel with lime mono number + serif name. (In the prototype the Slot/<image-slot> for these cards is passed position="50% 0%"; in production set object-position:50% 0% / top on these <img>s.)

⚠️ SAME RULES AS THE CAROUSEL — this is a drag/scrub slider driven by ONE persistent rAF lerp loop, NOT CSS scroll, scroll-snap, or a slider library. Port the exact code below.

How it works (the model)

The track is translated horizontally by a single number current (a negative px offset, 0 = start, -max = fully scrolled, where max = trackScrollWidth − viewportWidth). Two numbers live in a ref:

  • current — where the track is (what you render each frame).
  • target — where it's heading (set by drag / wheel / scrub).

One requestAnimationFrame loop runs for the component's whole life. Every frame:

  1. current += (target - current) * 0.085 (the lerp — buttery easing; snap when within 0.08).
  2. track.style.transform = translate3d(${current}px,0,0).
  3. Update the progress fill: scaleX(-current / max) → continuous 0→1.
  4. Parallax each image: shift it by its distance from viewport centre (subtle depth).

Exact implementation (port verbatim)

function Trends({ items }) {                 // items = the 9 vibes
  const vpRef = useRef(null), trackRef = useRef(null), fillRef = useRef(null), progRef = useRef(null);
  const st = useRef({ target:0, current:0, max:1, dragging:false, startX:0, startTarget:0, vel:0, lastX:0 });
  const clamp = v => Math.max(-st.current.max, Math.min(0, v));   // current/target ∈ [-max, 0]

  useEffect(() => {
    const vp = vpRef.current, track = trackRef.current; if (!vp || !track) return;
    const s = st.current; let raf;
    const measure = () => { s.max = Math.max(1, track.scrollWidth - vp.clientWidth); s.target = clamp(s.target); };
    measure();
    const ro = new ResizeObserver(measure); ro.observe(track); ro.observe(vp);   // recompute max on layout/img load
    const loop = () => {
      s.current += (s.target - s.current) * 0.085;
      if (Math.abs(s.target - s.current) < 0.08) s.current = s.target;
      track.style.transform = `translate3d(${s.current}px,0,0)`;
      const p = s.max > 0 ? -s.current / s.max : 0;
      if (fillRef.current) fillRef.current.style.transform = `scaleX(${Math.max(0, Math.min(1, p))})`;
      const vr = vp.getBoundingClientRect();
      track.querySelectorAll('.timg').forEach(img => {                            // subtle parallax
        const r = img.getBoundingClientRect();
        const rel = (r.left + r.width/2 - vr.left) / vr.width - 0.5;              // −.5 … .5
        img.style.transform = `translateX(${rel * -26}px) scale(1.14)`;
      });
      raf = requestAnimationFrame(loop);
    };
    raf = requestAnimationFrame(loop);
    return () => { cancelAnimationFrame(raf); ro.disconnect(); };
  }, []);

  // DRAG (pointer events on .slider-vp): track follows the finger 1:1, release adds inertia
  const onDown = e => { const s = st.current; s.dragging = true; s.startX = s.lastX = e.clientX; s.startTarget = s.target; s.vel = 0; e.currentTarget.setPointerCapture?.(e.pointerId); };
  const onMove = e => { const s = st.current; if (!s.dragging) return; s.target = clamp(s.startTarget + (e.clientX - s.startX)); s.vel = e.clientX - s.lastX; s.lastX = e.clientX; };
  const onUp   = () => { const s = st.current; if (!s.dragging) return; s.dragging = false; s.target = clamp(s.target + s.vel * 14); };
  // WHEEL (horizontal / shift+wheel)
  const onWheel = e => { const s = st.current; const d = Math.abs(e.deltaX) > Math.abs(e.deltaY) ? e.deltaX : e.deltaY; if (Math.abs(e.deltaX) > 4 || e.shiftKey) { e.preventDefault(); s.target = clamp(s.target - d); } };
  // SCRUB the progress bar (pointer-down/drag anywhere on it)
  const scrub = x => { const s = st.current, r = progRef.current.getBoundingClientRect(); const f = Math.max(0, Math.min(1, (x - r.left)/r.width)); s.target = -f * s.max; };
  const pDown = e => { e.preventDefault(); scrub(e.clientX); const mv = ev => scrub(ev.clientX); const up = () => { window.removeEventListener('pointermove', mv); window.removeEventListener('pointerup', up); }; window.addEventListener('pointermove', mv); window.addEventListener('pointerup', up); };

  // JSX:
  // <div class="slider-vp" ref={vpRef} onPointerDown={onDown} onPointerMove={onMove} onPointerUp={onUp} onPointerCancel={onUp} onWheel={onWheel}>
  //   <div class="slider-track" ref={trackRef}>
  //     {items.map(t => <div class="trend"><div class="timg"><img object-position:top .../></div><div class="tlabel">…</div></div>)}
  //   </div>
  // </div>
  // <div class="slider-bar"><div class="progress" ref={progRef} onPointerDown={pDown}><div class="progress-fill" ref={fillRef}/></div><span>Drag to explore</span></div>
}

Common failure modes (the bugs to avoid)

  1. No persistent rAF loop (animating only inside pointermove) → drag drags but release inertia and scrub don't ease — feels dead/stuttery. ✗ One loop runs always; pointer handlers only set target.
  2. setState per frame / animating via React state → 60 re-renders/s, jank. ✗ Keep current/target in a ref; mutate track.style.transform directly.
  3. A CSS transition: transform on .slider-track → fights the lerp, lag/rubber-banding. ✗ Remove it.
  4. max measured once before images load / not recomputed → wrong range, can't reach the end, or fill never hits 1. ✗ Use a ResizeObserver on track + viewport (as above).
  5. .trend without flex:none → cards shrink to fit, row never overflows, scrollWidth==clientWidth, max=1, nothing scrolls. ✗ flex:none + fixed width.
  6. Clamp sign flipped — current/target are negative ([-max, 0]); 0 = start. Don't clamp to [0, max].
  7. Driving it from page scroll — it's an independent drag/scrub, not scroll-linked.

Interactions & behavior summary

  • Scroll reveals: elements with .reveal start hidden (opacity 0 + a transform) and animate in when they enter the viewport. Four variants exist (a Tweak): fade / up (translateY 46px) / scale (.92) / blur (blur 14px). Default = up. Transition .9s var(--ease-out), staggered via data-delay (.08s steps). In production, prefer IntersectionObserver or Framer Motion whileInView. (The prototype uses a scroll-position rАF check because IO is unreliable in the preview iframe — not needed in a real app.)
  • Hero: pointer-parallax + scroll tilt/fade (see §2).
  • Carousel: click / arrows / drag (see §4).
  • Style slider: drag + inertia + progress scrub + wheel + image parallax (see §5).
  • Modal: validation-gated submit, success state, Esc/scrim/✕ close (see §8).
  • Reduced motion: @media (prefers-reduced-motion:reduce) collapses reveal transition durations — honor this in production.
